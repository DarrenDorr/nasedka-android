# НАСЕДКА — ANDROID SECURITY & RELIABILITY BASELINE v1.0

**Дата:** 17.11.2026. **Класс:** High Assurance для уведомлений, безопасности обновлений, пользовательских данных и публикации. **Область:** будущий Android-проект «Наседка», сначала для «Несушки», далее другие инкубаторы. Применять совместно с `Nasedka_Security_OS_v3.docx`, `Nasedka_Security_Prompts_v3.md`, `Nasedka_SECURITY_PROFILE.yaml`.

> ВАЖНО: приложение — электронный помощник, а не сертифицированная система мониторинга инкубатора. Без подключённых проверенных датчиков и аппаратной интеграции оно НЕ измеряет фактические °C/влажность, НЕ фиксирует отключение питания и НЕ гарантирует доставку напоминания на каждом устройстве. Ручные значения отмечаются как введённые человеком. Нельзя подменять «нет измерения» нулём, нормой или отсутствием аварии.

## 1. Статусы и правила

`CONFIRMED` — подтверждено фактической реализацией/источником; `PLANNED` — пожелание; `UNKNOWN` — данных нет; `MISMATCH` — расхождение; `NOT_RUN` — тест не запущен; `N/A` — не применяется с основанием. Решения о безопасности: `BLOCK / HIGH / REVIEW / PASS / UNKNOWN / NOT_RUN / N/A`. PASS не означает «приложение защищено полностью». При отсутствии репозитория нельзя заявлять, что код проверен.

## 2. TRUST BOUNDARIES

- `USER` → ввод параметров, разрешения, настройки; пользовательские значения могут быть ошибочны.
- `INCUBATION_PLAN` → заранее выбранный/проверенный вид и модель, длительность инкубации, контролируемые даты; расписание критично.
- `ANDROID_OS` → уведомления, alarm permissions, системные ограничения, энергосбережение, переустановка, время/часовой пояс.
- `LOCAL_DATA` → партии/журналы/напоминания, экспорт и восстановление; нельзя потерять из-за рекламы/обновления.
- `NETWORK` → GitHub releases/новости/рекламный SDK/магазины; ни один внешний ответ не обладает правом менять план пользователя или выполнять код.
- `APP_UPDATE` → Play / RuStore / GitHub должны иметь разные, допустимые для каждого канала пути и общую проверку подписи/идентичности.
- `FUTURE_HARDWARE` → любой BLE/Wi-Fi/USB должен проходить отдельно admission и не обещать аварийный мониторинг без E2E-тестов.

## 3. Security invariants (NSD)

| ID | Обязательный инвариант / негативный тест |
|---|---|
| NSD-001 | Базовый календарь и локальный журнал работают офлайн и без согласия на рекламу. |
| NSD-002 | При отсутствии физического датчика никакая «текущая температура/влажность/питание» не подаётся как измеренная устройством. |
| NSD-003 | Изменения параметров инкубации имеют источник: модель+версия руководства, вручную изменено или пользовательский профиль. |
| NSD-004 | Старт партии, вид, выбранный срок, плановая дата вывода вычисляются детерминированно; есть тесты пограничных дат. |
| NSD-005 | Переход через полночь, часовые пояса, DST и перевод часов не смещает даты молча. |
| NSD-006 | На Android 13+ `POST_NOTIFICATIONS` корректно запрашивается и обрабатываются отказ/отзыв. |
| NSD-007 | Приложение не объявляет гарантированно точные уведомления при отсутствии exact-alarm права/одобрения политики. |
| NSD-008 | `USE_EXACT_ALARM` не добавляется без документированной применимости к Android/Google Play policy. |
| NSD-009 | При `SecurityException`/запрете `SCHEDULE_EXACT_ALARM` используется безопасный разрешённый fallback. |
| NSD-010 | WorkManager не рекламируется как точный таймер с гарантией доставки в секунду. |
| NSD-011 | После перезагрузки, force-stop, обновления, смены времени/часового пояса и восстановления приложения состояние расписания сверяется с локальной БД. |
| NSD-012 | При отказе в уведомлениях сохраняется видимый в приложении список предстоящих и пропущенных задач с понятным предупреждением. |
| NSD-013 | Повторное планирование одной задачи не создаёт лавину дублей: стабильные event IDs / dedup/idempotency. |
| NSD-014 | Пользователь видит дату/время, вид, партию и причину уведомления; уведомление не раскрывает лишнее на lock screen. |
| NSD-015 | Кнопки «выполнено», «отложить» и «пропустить» не отмечают действие выполненным до подтверждения обработки. |
| NSD-016 | Отменённая или завершённая партия не генерирует устаревших активных напоминаний. |
| NSD-017 | Несколько партий и разные расписания не перепутываются, включая совпадающие даты и имена. |
| NSD-018 | Уведомление об окончании переворота привязано к **плановой дате вывода**, а не жёстко к «дню 19» для всех видов. |
| NSD-019 | Ручной и автоматический переворот различаются; приложение не требует ручного переворота при выбранном автоматическом сценарии. |
| NSD-020 | Противоречие интервала автоматического переворота в руководстве «Несушка» (4 часа заводская настройка vs около 1 часа в другом разделе) помечено VERIFY и не превращается в единый факт. |
| NSD-021 | Вода/овоскопирование/влажность отображаются как рекомендации под выбранный профиль, не универсально для всех пород/инкубаторов. |
| NSD-022 | При потере данных/ошибке миграции приложение не сбрасывает партию и напоминания молча. |
| NSD-023 | Приложение, установленное из Google Play, не скачивает и не устанавливает APK для самообновления с GitHub. |
| NSD-024 | Google Play-flavor использует Google Play in-app updates/ссылку на Play. |
| NSD-025 | RuStore-flavor использует RuStore SDK/ссылку на RuStore и проверяет его предпосылки. |
| NSD-026 | GitHub-flavor — самостоятельный вариант дистрибутива; установка APK только по действию пользователя и через системный механизм с согласием. |
| NSD-027 | GitHub update manifest имеет фиксированный origin, проверяемую криптографическую подпись или эквивалентную цепочку доверия; SHA-256 с того же взломанного канала **недостаточно**. |
| NSD-028 | Подпись APK должна соответствовать установленному package/signing identity; key rotation отдельно проходит миграцию. |
| NSD-029 | Версии монотонны, downgrade не допускается по умолчанию, asset/package/channel mismatch блокирует обновление. |
| NSD-030 | Проверка релиза раз в 24 часа при открытии не ломает офлайн-режим; есть manual refresh, timeout, ETag/backoff и отсутствие бесконечных ретраев. |
| NSD-031 | Сетевые ответы GitHub/новостей/рекламы не изменяют permission, shell, установку пакетов или инкубационный план. |
| NSD-032 | Новости — только контент из allowlisted источника; WebView JavaScript/bridge/file access не включаются ради новостей по умолчанию. |
| NSD-033 | Новости и реклама не маскируются под системные сообщения, срочные напоминания или установку обновления. |
| NSD-034 | Реклама не показывается внутри срочного уведомления, поверх формы ухода за яйцами или в Android notification shade/lock screen. |
| NSD-035 | Отказ от рекламы/недоступность сети/ошибка SDK не блокируют дневник и инкубационные напоминания. |
| NSD-036 | До отправки рекламы data flows и consent решены по региональным/магазинным требованиям; privacy policy и Data safety соответствуют фактическим SDK. |
| NSD-037 | Ни одно SDK не получает ключи, заметки или расписание партии, если это не требуется, не раскрыто и не согласовано. |
| NSD-038 | Нет ненужных permissions (SMS, контакты, геолокация, call log, overlay, all-files access, package install в Play-flavor). |
| NSD-039 | Экспорт/импорт выполняется безопасно: schema version, ограничение размера, парсер, path traversal, dedup, partial-import rollback, no arbitrary code. |
| NSD-040 | Backup/reinstall/update не создают повторные уведомления и не удаляют журнал без предупреждения. |
| NSD-041 | Android components `exported=false` по умолчанию; deep links/Intent inputs валидируются. |
| NSD-042 | HTTPS по умолчанию; debug trust exceptions не переносятся в release; secrets не встроены в APK. |
| NSD-043 | GitHub Actions, Gradle plugins, Android SDK, native SDK/ads SDK проходят admission и pinning, SBOM, SCA, secret scan. |
| NSD-044 | Play/RuStore/GitHub signing keys защищены; CI из недоверенных PR не может подписывать релиз или публиковать его. |
| NSD-045 | При любом инкубаторе будущего производителя применяется модель capability/profile; нельзя объявлять совместимость без проверок модели. |
| NSD-046 | Марка «Несушка» упоминается как совместимая модель без утверждения об официальном партнёрстве/одобрении. |
| NSD-047 | Явные ссылки на происхождение рекомендаций и отказ от гарантии успешной инкубации; пользователь видит необходимость ручной проверки оборудования. |
| NSD-048 | Все offensive/security tests выполняются только в своей test-среде и в рамках правил использования ChatGPT. |
| NSD-049 | Алгоритм уведомлений тестируется на реальных устройствах/эмуляторах по матрице Android и battery OEM; тест одной модели телефона не равен PASS для всех. |
| NSD-050 | Журнал фиксирует фактическое действие и время пользователя отдельно от планового уведомления; нельзя приравнивать «уведомлено» к «сделано». |

## 4. App architecture proposal (NOT IMPLEMENTED)

Рекомендуемое разбиение — предметные слои `IncubationPlan` / `IncubatorProfile` / `Batch` / `Events` / `ReminderScheduler` / `Journal` / `NewsReader` / `UpdateCoordinator` / `AdsConsentGate`. Локальная БД с инвариантами — источник истины; Android receiver/worker восстанавливает **производные** будильники. У профиля инкубатора — версионирование, происхождение, поддерживаемые функции; неизменные планы уже начатых партий нельзя тихо переписать при обновлении справочника. Конкретный стек выбирается после репозитория (Kotlin/Compose не объявляется уже выбранным).

## 5. Android notifications: правильная модель

- Notifications permission — пользовательский выбор; при отказе запланированные записи остаются в локальной БД; при следующем открытии показывается понятная диагностика.
- Для приблизительных периодических проверок — WorkManager; он не гарантирует точный час. Для конкретного user-facing напоминания выбрать допустимый Android AlarmManager API на основе policy и реальной необходимости; запрет exact alarm не должен приводить к crash.
- Не объявлять `USE_EXACT_ALARM` только ради удобства публикации. `SCHEDULE_EXACT_ALARM` (если вообще допустим/нужен) запрашивается с объяснением и с обработкой отзыва. `POST_NOTIFICATIONS` для Android 13+.
- На Android 14+ у новых установок exact-alarm доступ может быть отказан по умолчанию. Фоновые ограничения, force-stop, battery saver и OEM-прошивки исключают обещание стопроцентной точности.
- Перепланирование — из БД с устойчивыми UUID, после `BOOT_COMPLETED`, `TIMEZONE_CHANGED`, `TIME_SET`, update/reopen там, где OS позволяет. Не обходить ограничения энергосбережения скрытыми службами/foreground services.
- Время: сохранять event instant, zone ID, локальную пользовательскую дату и правила события; тестировать округления суток, leap year, DST/смену пояса, переход 23:59.

## 6. Инкубация: источник рекомендаций

Фактический документ `incubat_2021.pdf`: закладка и безопасность — разделы 6–7; вода/влажность — 7.2–7.3; заводская температура **38.0°C** и начальная настройка УП **4 часа** — 7.5; перевод — раздел 8; прекращение переворота за **2 дня до планируемого вывода** — 8.4; овоскопирование **7–8 и 11–13 сутки** — 8.5; длительность куры **21**, гуси **28–30**, утки **28–33**, индейки **28**, перепела **15–17** дней — 8.7. В разделе 8.2 УП также описан как **1 раз в час** (вариант/сноска); ВЫВОД: нельзя автоматически задавать период всех модификаций как 1 или 4 часа. Для каждого вида, породы, инкубатора пользователь подтверждает применимость настроек; значения не заменяют инструкцию актуальной модели и консультацию специалиста.

Также памятка по электробезопасности в руководстве (разд. 4) должна оставаться справочной информацией, не инструкцией вскрывать прибор. Не реализовывать управление силовыми цепями 220В без отдельной сертификационной/технической экспертизы.

## 7. Distribution/update threat model

| Канал | Источник обновления | Проверка | Запрет |
|---|---|---|---|
| Google Play | Play In-App Updates или переход в Play | штатная identity/signature, Play flow, targetSdk gate | скачивание/самоустановка GitHub APK, `REQUEST_INSTALL_PACKAGES` без допустимого core purpose |
| RuStore | RuStore in-app update SDK/страница | RuStore prerequisites, identity/signing & tested flow | обход пользовательского подтверждения, подмена download URL |
| GitHub | конкретный официальный GitHub Releases | pinned repo + signed release metadata + sha256 + APK signing identity + user confirmation + channel guard | установка без согласия, arbitrary URL, downgrade, cross-channel signature mismatch |

В UI можно показывать новую версию и новости о релизе; **оповещение ≠ право обновить приложение сторонним APK**. Для Play/RuStore приложение может прочитать публичные release notes на GitHub, но передавать управление установкой только своему магазину. Обозначать канал текущей сборки в экране «О программе».

## 8. Advertising & privacy

Объявления отделять от контента, избегать интерстициалов при вводе, выводе/повороте/напоминаниях. Реклама не должна мешать кнопке «Отметить выполненным». До интеграции SDK нужен data-flow inventory, проверка версии/владельца SDK, политика конфиденциальности, региональный consent, Google Play Data safety и требования RuStore. Не делать жёсткую зависимость core-функций от рекламного SDK. Метрики рекламы не путать с журналом инкубации. Ads SDK нельзя загружать до прохождения необходимых consent/policy gates.

## 9. NEWS/remote content

Подписанные GitHub release metadata не равны новостям; новость никогда не запускает `Intent.ACTION_INSTALL_PACKAGE` и не переопределяет endpoint. Защищать от HTML/script/deeplink/scheme injection, open redirects, огромных ответов, небезопасных HTML и фишинговых ссылок. Ограничение размера, таймаут, local fallback. Доверенные домены — только в конфиге приложения/проверенной конфигурации, не в новостном тексте.

## 10. Release blockers

`BLOCK`: Play build включает self-update APK flow, невалидационный GitHub update manifest или подмена signing key, отсутствие гарантированной локальной сохранности партия/напоминаний при миграции, воспроизводимые критические ошибки времени/дней, некорректные напоминания «остановить переворот» из-за перепутанного вида, реклама блокирует срочное действие, app falsely claims actual power/temp measurement, secret/signing key leak, policy-required disclosures отсутствуют, обход Android permission policy, Critical reachable security issue, собранный APK отличается от проверенного релизного digest.

`REVIEW`: exact alarm permission, новый рекламный SDK, первый RuStore/Play update, изменение срока/правил плана, новые аппаратные интеграции, publisher/vendor-brand claims, cloud/sync/accounts, неподтверждённые OEM limitations.

## 11. Evidence

Для каждого теста: `commit`, flavor, `versionCode`, device/emulator brand/model, Android API, OEM/battery saver, notifications/exact-alarm state, timezone, event/batch ID, expected/actual, log без секретов, screenshot, PASS/FAIL/NOT_RUN. Для релиза: artifact digest, build provenance, signing cert fingerprint, SDK versions, data safety/privacy policy link, магазинная декларация permissions/ads, release channel, backup/restore test, review approver.

## 12. Разрешённое security testing

Только собственные репозитории, тестовые APK, эмуляторы/устройства с разрешением. Не выполнять действия по взлому стороннего GitHub, рекламного SDK, магазина, инкубатора/сети производителя. Из интернет-публикаций строить безопасные threat-invariants/tests, а не запускать чужой PoC. Выполнять требования использования ChatGPT. При нехватке инструментов `NOT_RUN`/`UNKNOWN` — не «PASS».
