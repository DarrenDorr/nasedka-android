# Подпись отладочных APK и сохранение пользовательских данных

Android разрешает установку новой версии поверх старой **только при совпадении package name и подписи** (с учетом допустимой ротации), а также при корректном versionCode.

При стандартном GitHub-hosted runner новый `~/.android/debug.keystore` может генерироваться на каждом запуске. Поэтому CI-сборка, прошедшая тесты, НЕ гарантирует безопасное обновление APK поверх уже установленной версии. **Нельзя просить пользователей удалить приложение с единственной копией данных.**

Для постоянного тестового сертификата предусмотрены зашифрованные GitHub Actions Secrets:
- `NASEDKA_DEV_KEYSTORE_B64`
- `NASEDKA_DEV_STORE_PASSWORD`
- `NASEDKA_DEV_KEY_ALIAS`
- `NASEDKA_DEV_KEY_PASSWORD`

В репозитории нет приватного сертификата. Если все секреты доступны, workflow временно восстанавливает keystore на runner и использует его только для debug-сборок. Иначе APK соберётся со стандартным непостоянным debug сертификатом; артефакт содержит `signing-status.txt` с явным предупреждением. **Никогда не передавайте приватный ключ в чат или публичный репозиторий.**

Это не релизная подпись. Для Play / RuStore / GitHub-production требуется отдельный защищённый сертификат, правила ключей, проверки digest/SHA-256 и процесс обновления с сохранением данных.

## Gate
- [ ] Постоянный тестовый сертификат настроен.
- [ ] SHA-256 сертификата сохранён локально владельцем.
- [ ] Обновление APK vN → vN+1 на Honor X7b прошло с сохранением обеих баз.
- [ ] Полный бэкап успешно восстановлен на тестовой установке.
- [ ] Production release keys / Play App Signing подготовлены отдельно.
