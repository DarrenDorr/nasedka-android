# Экспорт / восстановление v0.7.0-dev — политика защиты данных

## Порядок

1. Пользователь явно выбирает файл через Android Storage Access Framework.
2. Экспорт — полный сериализованный JSON: 3 таблицы инкубации + 11 таблиц хозяйства, настройки времени, текущая версия схемы каждого файла. Записи не уходят в сеть; файл может содержать данные хозяйства.
3. Перед импортом: проверка формата/версий, лимит 24 МБ, валидация времён уведомлений.
4. Автоматически создаётся приватная предимпортная копия JSON.
5. Новые базы разворачиваются во временных файлах; проверяются PRAGMA integrity_check и ссылочная целостность.
6. Замена двух файлов защищена маркером. Если процесс завершается до удаления маркера, при следующем запуске Application откатывает предшествующие файлы.
7. При успешном восстановлении на главном экране пересоздаются напоминания инкубации и хозяйственных задач.

## Важные ограничения

- Схема новых модулей отделена от существующей инкубационной базы.
- Текущий импорт **заменяет**, а не объединяет истории и требует явного согласия.
- Настройки каналов звука Android и системные разрешения нельзя экспортировать обычным JSON: после восстановления проверить их вручную.
- Для аварийного восстановления нельзя удалять приложение: с удалением исчезнут защищённые приватные резервные файлы.
- Это технический механизм, НЕ подтверждение тестирования реальной миграции на физическом устройстве.
- Не проверяйте импорт на единственной копии важных данных до полноценной тестовой матрицы.

**Версия 0.8.0-dev:** поддерживается хозяйственная база v2 (добавлены датировка групп и таблица `flock_notes`), при импорте старой v1 пустая таблица `flock_notes` создаётся автоматически. Добавлена очистка sidecar-файлов SQLite только после контрольной точки журнала; импорт прекращается, если журнал всё ещё содержит незафиксированные данные. В настройках сохраняется расписание проверок наседки. Физическое QA аварийного восстановления обязательно.

Проверяется ссылка `incubator_transfers.flock_id` и положительное количество. См. [отчёт и тесты](R1_1A_BACKUP_VALIDATION_2026-11-25.md).
