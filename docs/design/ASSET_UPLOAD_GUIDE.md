# Перенос 43 оригинальных UI-макетов в GitHub

**Статус 2026-11-25:** все 43 оригинальных PNG включены в GitHub. Размеры и Git blob SHA-1 совпали с исходным ZIP; SHA-256 всех оригиналов в ZIP проверены. Отдельно требуется подтвердить результат CI. Инструкция ниже сохранена для аварийного восстановления, повторно импортировать файлы не нужно.

## Готовый комплект

Из локального полного архива с точными исходными изображениями создан `Nasedka_GitHub_Design_Assets_2026-11-23.zip`. Размер около 85,9 МиБ, SHA-256 ZIP:

`bda897b6dbe0bba800b26be41862623e77ba962e9cbbd30259eca58e7c647457`

В комплекте ровно 45 записей:
- `docs/design/assets/DES-000.png` … `docs/design/assets/DES-042.png`: 43 оригинальных изображения, **байты не менялись**;
- `docs/design/asset_checksums.sha256`: 43 хеша;
- `docs/design/IMAGE_MANIFEST.csv`: ID, исходное имя, статус, нормализованный путь, SHA-256, размер и размеры картинки.

**В ZIP нет** оригинального руководства производителя инкубатора, ключей подписи и персональных данных.

## Доставка в репозиторий

Первоначально прямой перенос был недоступен; 25.11.2026 перенос выполнен через Git blob/tree/commit с проверкой исходных идентификаторов. При необходимости аварийного восстановления используйте комплект ниже. Не публиковать сам ZIP вместо отдельных PNG в дереве репозитория.

### С GitHub Desktop (Windows)

1. Установить/открыть GitHub Desktop, клонировать `DarrenDorr/nasedka-android`.
2. Распаковать ZIP **в корень копии репозитория**, чтобы появился путь `docs/design/assets/DES-000.png`. Существующие файлы проекта не заменять.
3. Убедиться, что появились ровно 43 PNG, проверить `docs/design/asset_checksums.sha256`.
4. Создать коммит с сообщением `docs: add original approved Nasedka design references` и отправить на GitHub.
5. В GitHub Actions дождаться **Design reference integrity → success** (должны совпасть все 43 SHA-256).

Можно использовать другое средство загрузки Git. Главное — сохранить структуру каталогов и оригинальные байты.

## Проверка

В репозитории уже есть `tools/verify_design_assets.py` и workflow `.github/workflows/design-reference-integrity.yml`. Проверка запускается на изменениях `docs/design/assets/**` и может запускаться вручную. До загрузки всех PNG она **должна считать комплект неполным**, это не ошибка Android-кода.

Локально из корня клонированного репозитория:

```powershell
python tools/verify_design_assets.py
```

Ожидаемый результат: `PASS: all 43 approved-or-archived original PNG files present and byte-identical`.

## После успешной проверки

1. В `docs/PROJECT_STATUS.md` отметить, что все 43 графических файла реально в GitHub.
2. В `docs/design/SCREEN_REGISTRY.md` добавить относительные пути и ссылки к экранам.
3. Сопоставить макеты с текущими исходниками по `docs/design/IMPLEMENTATION_AUDIT_2026-11-23.md`.
4. Проводить перенос дизайна в Android код **по одному разделу**, не меняя утверждённый стиль и не разрушая старые данные.

**Согласование картинки ≠ реализация UI в APK.** Даже успешный Actions SHA-256 доказывает лишь сохранность изображений.
