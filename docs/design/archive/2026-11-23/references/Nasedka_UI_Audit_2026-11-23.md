# «Наседка» — сводная проверка интерфейса и логики перед реализацией

Дата: 23.11.2026  
Статус: проектная ревизия на согласование. **Не означает, что интерфейс реализован или протестирован на Android.**  
Основание: ранее согласованные макеты приложения, первичный точный эталон `наседка_фермерский_ui_концепт.png`, спецификации «Главная» и «Инкубация», последующие согласования логики.  

## 1. Неприкосновенные решения о дизайне

1. Сохранять утверждённые цвета, картинки, типографику, радиусы, карточки, композицию и навигационные элементы. Не менять оформление без отдельного одобрения.
2. Внизу ровно четыре глобальные вкладки: **Главная, Новости, Журнал, Настройки**. Инкубация, поголовье, корма, финансы и отчёты — вложенные модули Главной, не дополнительные нижние вкладки.
3. Иконку приложения разрабатывать последней.
4. Прежде чем изменять исходники, согласовывать макеты отсутствующих состояний: пустые списки, ошибки, запрет разрешений, длинные названия, много записей, клавиатура и поворот экрана.
5. Несоответствие на некоторых иллюстрациях: вложенные экраны подсвечивают «Журнал» или «Настройки» даже там, где пользователь пришёл через «Главную». Для реализации требуется единое правило: вкладка соответствует активному глобальному разделу или, для вложенных рабочих экранов, контексту перехода; не придумывать новую нижнюю вкладку.

## 2. Карта навигации (без функциональных дублей)

```text
Нижние вкладки
├── Главная
│   ├── Инкубация
│   │   ├── В инкубаторе: способ → модель → комплектация → иллюстрированная инструкция → закладка
│   │   ├── Под наседкой: подготовить / птица уже села → проверка → закладка
│   │   └── Закладка → сегодня → календарь → события → вывод → учёт молодняка
│   ├── Поголовье → группы → карточка → уход / движение / история
│   ├── Корма и запасы → остатки → карточка корма → поступление / расход
│   ├── Финансы → поступления и выплаты → карточка операции
│   └── Отчёты → сводка → яйценоскость / инкубация / поголовье / экономика → экспорт
├── Новости → лента / категории → статья / новости приложения
├── Журнал → единый список ↔ календарь → фильтры → событие → корректировка / история
└── Настройки → хозяйство / уведомления / данные и копии / правила / о приложении

Колокольчик на Главной → Центр напоминаний → одна задача → выполнить / напомнить позже
```

При нажатии «Назад» возвращаться в предыдущий рабочий контекст, сохраняя введённые и ещё не отправленные пользователем данные; при повороте телефона — те же формы и окно/шаг мастера.

## 3. Правила, исключающие дублирование

| Событие | Единственный первичный факт | Где отображается результат |
|---|---|---|
| Покупка 20 кг корма за 800 ₽ | Одна подтверждённая закупка с идентификатором и финансовой связью | +20 кг в запасах; расход 800 ₽ в финансах; событие в журнале; отражение в отчётах |
| Кормление 2 кг | Одно списание запаса | −2 кг в запасах, событие в журнале, расход корма по группе; **не новая денежная оплата** |
| Перевод 6 птиц между группами | Одно перемещение из A в B | −6 в A, +6 в B, общий итог не меняется |
| Вывод 90 птенцов | Одна запись о фактическом выводе по закладке | 90 в результате инкубации; один связанный приход в группу молодняка; журнал / отчёты |
| Овоскопирование | Отдельная запись осмотра | Осмотр не уменьшает яйца сам: сокращение числа только после явно подтверждённого выбытия |
| Выполнение напоминания | Смена состояния существующей задачи | Задача закрыта, изменение видно в журнале; копия задачи не создаётся |
| Корректировка | Новая ревизия того же события, не второй исходный факт | Пересчёт всех зависимых итогов, сохранение прежнего значения и причины |

Обновления связанных сущностей следует выполнять атомарно: если часть действия не сохранена, не должен появиться расход денег без поступления корма или приход птицы без связи с инкубацией.

## 4. Инкубация: инварианты количества

- Первоначально заложено — неизменный факт запуска партии (при ошибочном вводе исправление через историю).
- Текущее количество яиц — подтверждённый остаток; не отрицательное.
- Овоскопирование ≠ удаление; не считать сомнительное яйцо автоматически удалённым.
- Вылупление, выбытие яиц и отсутствие результата — разные исходы.
- Для примера: 104 заложено − 6 удалено = 98 к выводу; 90 вылупилось → остаются **8 яиц с ещё не установленным результатом**, пока пользователь не укажет исход.
- Процент от первоначальной закладки: 90 / 104 ≈ 86,5%; процент от яиц, оставленных к выводу: 90 / 98 ≈ 91,8%. Метрику нужно подписывать, а не объединять в безымянное «% выводимости».
- Под наседкой: дата начала может быть неизвестна или приблизительна; в таком случае точный день/процент не показывать. Не назначать курице ручные перевороты или аппаратные режимы терморегулятора.
- «Добавить в поголовье» — учёт вылупившихся птенцов, **не физическое отделение от наседки**. Повторное добавление этой же партии блокируется или оформляется как проверенная коррекция.

## 5. Применимость рекомендаций

- В инкубаторном сценарии сначала выбирается точная линейка/модель (БИ-1, БИ-2 либо другая), затем конфигурация: вместимость, способ переворота, терморегулятор, вентилятор, резервное питание и прочее — только если предусмотрено производителем.
- После вводного экрана с кликабельной официальной инструкцией идут настоящие постраничные шаги с изображением, конкретными действиями и подтверждением. Фразы «смотрите инструкцию» вместо действия недопустимы.
- Указывать источник, редакцию документа и условия применимости; не смешивать оборудование разных лет и версий.
- Периодическое охлаждение яиц не равно постоянной вентиляции инкубатора; нормы не назначать без проверенного источника под конкретный вид/режим.
- Советы по молодняку зависят от вида птицы, возраста, назначения и условий; назначения лекарств и диагностика — не автоматизированы. При сомнениях рекомендовать специалиста/ветеринара.
- Политика первого запуска: информация рекомендательная, не гарантирует результата, не заменяет оборудование, официальные инструкции и консультации. Полные условия и политика конфиденциальности доступны до согласия и позднее в настройках.

## 6. Надёжность и конфиденциальность

- Никакой обязательной регистрации, точного адреса или GPS. Поле региона отсутствует сейчас; позднее возможен **необязательный ручной выбор региона**, без доступа к точной геолокации.
- Температура, влажность и состояние инкубатора — ручные записи, если нет подтверждённого интегрированного устройства. Пустое измерение так и показывать.
- Для HONOR/Android: отдельное тестирование разрешения уведомлений, каналов и звука, задач при заблокированном экране, после перезапуска, после обновления и при энергосбережении; подсветка экрана не гарантируется ОС.
- Запланированное событие, его доставка, подтверждение, пропуск и повторное напоминание — разные статусы. Нельзя отмечать задачу выполненной только потому, что доставлено уведомление.
- Резервная копия ≠ экспорт отчёта. Полная копия содержит связанные записи, настройки и вложения. Проверять совместимость, целостность, предупреждать о замене, сохранять возможность отката или предварительную копию текущего состояния.
- Опции «автоматическое копирование», «PDF/Excel экспорт», «PIN», дополнительные каналы обновлений обозначать **планируемыми**, пока нет проверенной реализации.
- Журнал изменений сохраняется при обычной отмене/архивировании; отдельная осознанная функция полного удаления личных данных и резервных копий должна быть возможна.

## 8. Состояние по разделам

| Раздел | Визуальное направление | Следующая работа |
|---|---|---|
| Главная | Зафиксирован точный исходный эталон | Состояния нулевых данных, уведомлений и больших значений |
| Инкубация в аппарате | Согласованы мастер, подготовка, текущая закладка, журнал, вывод | Модельные инструкции, применимость режимов, пустые/ошибочные состояния |
| Под наседкой | Согласованы два сценария, наблюдение, вывод, выращивание | Неизвестная дата и нештатные ситуации без ложных сроков |
| Поголовье | Согласованы группы, движение, уход | Журнал корректировок, связь с выводом; **пока не спроектирован отдельный ввод сбора яиц** |

| Финансы | Согласованы операции и краткая сводка | Категории, корректировки, различие оплаты и себестоимости |
| Отчёты | Согласован визуальный формат | Проверенные формулы и контекст отсутствующих данных |
| Журнал | Объединённый реестр, календарь, фильтры, карточка, история | Убрать отдельные повторяющиеся сводки и защитить операции |
| Новости | Согласована лента, материалы, обновления | Источники, проверка советов, офлайн и рекламное разграничение |

| Центр напоминаний | Согласован вид и действия | Проверка сценариев Android/HONOR и непротиворечивые состояния |

## 9. Критерии допуска к переносу UI в код

1. Для каждого утверждённого экрана есть точная ссылка на его картинку-эталон и список интерактивных зон.
2. Утверждены пустые/ошибочные/загруженные состояния и поведение при повороте и возврате в приложение.
3. Согласованы наименования чисел и формулы, особенно «выводимость», «сейчас яиц», «поголовье», «доход», «расход», «себестоимость».
4. Для каждой операции указан её первичный источник, связи и правила отмены/редактирования.
5. Проверены применимость и источники всех биологических и технических рекомендаций.
6. Составлены тесты уведомлений, восстановлений, миграций, связи операций и защиты от дублей.
7. Реализация идёт по модульным этапам, с визуальным сравнением с утверждёнными изображениями. Код не менять до отдельной команды о начале реализации.

**Следующий дизайн-шаг:** согласовать отсутствующий рабочий экран «Сбор яиц» (ежедневная запись по группе несушек, доступный остаток и связь с продажей), а также обработку пустых/ошибочных состояний в существующих макетах.

**Итог:** основные разделы визуально согласованы. Обнаруженные вопросы касаются прежде всего согласованности состояний и данных, а не необходимости нового дизайна. Этот документ фиксирует проектные решения, но не результаты тестов кода.
