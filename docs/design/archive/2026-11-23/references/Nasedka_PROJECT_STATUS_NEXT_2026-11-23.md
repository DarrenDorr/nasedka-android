**Актуализировано:** 23 ноября 2026 года  
**Репозиторий:** https://github.com/DarrenDorr/nasedka-android (ветка `main`)  
**Текущий ориентир исходников:** `0.9.0-dev` — **по README и ROADMAP в GitHub**, без независимой проверки сборки и всего функционала в рамках этой ревизии.  
**Фаза работы:** концепция интерфейса почти завершена; собираем финальную спецификацию, затем сверяем её с существующим кодом.  
**Правило:** не переписывать проект с нуля, не изменять утверждённое оформление, не начинать реализацию и не менять GitHub без отдельной команды пользователя.

## 0. Точка продолжения — читать первой

**ПОСЛЕДНЕЕ СДЕЛАННОЕ:** согласованы ключевые экраны и их логика, включая «Сбор и учёт яиц». 23.11.2026 подготовлен макет для пустого состояния, ошибок ввода, длинных списков и восстановления черновика после поворота/закрытия. Это **визуальный проект, не доказательство технической реализации**. Последний макет показан пользователю; отдельного формального «утверждаю» после показа не было.

**СЕЙЧАС:** завершить реестр *всех* утверждённых экранов и переходов (экран → ссылка на эталон → элементы/действия → состояния → источник данных → статус). Устранить смысловые расхождения макетов, не менять внешний вид.

**СЛЕДУЮЩЕЕ КОНКРЕТНОЕ ДЕЙСТВИЕ:** составить матрицу UI–функции и сверить её с реальным исходным кодом ветки `main` (`0.9.0-dev`), отметить `РЕАЛИЗОВАНО / ЧАСТИЧНО / НЕТ / ТРЕБУЕТ ТЕСТА`. Не писать новые экраны, пока не определено, что уже существует. После этого сформировать небольшие последовательные задачи для реализации и тестирования.

**НЕ ПОВТОРЯТЬ:** ранее утверждённые макеты и концепции, вновь выбирать нижние вкладки, менять темы, начинать разработку заново или вновь предлагать одни и те же разделы без явного запроса.

## 1. Неприкосновенные решения

- Базовый дизайн — точно согласованный кремово-зелёный фермерский стиль «Наседки», скруглённые карточки, читаемая русская типографика, иллюстрации птицы. Рисовать новые страницы в этом стиле; **не перерабатывать его самостоятельно**.
- Ровно четыре нижние кнопки: **Главная · Новости · Журнал · Настройки**. Инкубация, поголовье, сбор яиц, корма, финансы, отчёты — вход с Главной; напоминания — по колокольчику; никаких дополнительных нижних вкладок.
- Иконку приложения создавать **в последнюю очередь**.
- Сначала согласуем внешний вид/логику, затем переносим в действующий Android-проект без уничтожения существующих возможностей.
- Базовые данные локальные и доступны офлайн. Нет обязательной учётной записи, GPS и точного адреса. Регион — **не сейчас**; позднее — только необязательное ручное поле.
- «Одно реальное действие — один исходный факт — связанные представления во всех разделах». Не плодить запись о покупке в каждой БД отдельно без гарантированной связности. Журнал — общая история, а не дополнительная бизнес-операция.
- Все советы носят информационный характер. Предупреждение при первом запуске; ссылки на официальные инструкции и проверенные источники; при проблемах с птицей рекомендовать специалиста/ветеринара. Никаких универсальных неустановленных режимов.
- Температуру/влажность ввести можно вручную; **без физических датчиков приложение их не измеряет**.
- Новости отдельно от личного журнала. Реклама в будущем и не на критических экранах, политика конфиденциальности прежде подключения SDK.
- Исходники открытые, лицензия Apache-2.0. Разные политики обновления GitHub/Google Play/RuStore; без подписанного пользовательского релиза нельзя считать debug APK публичным обновлением.

## 3. Контрольные инварианты (не ломать при разработке)

1. **Яйца:** 104 заложено − 6 подтверждённо удалено = 98 к выводу; 90 птенцов вылупились; у 8 оставшихся яиц статус **не установлен**, пока пользователь не запишет исход. Выводимость от всей закладки и от допущенных к выводу — два разных процента.
2. **Наседка:** неизвестная дата начала не превращается автоматически в точный день. Не предлагать ручной поворот/терморегулятор. «Добавить молодняк» — учётная операция, не физическое отделение птенцов.
3. **Поголовье:** перенос между группами не меняет общую численность. Перенос вылупившихся в поголовье происходит только один раз; корректировки отдельно.
4. **Яйца хозяйства:** сбор 24, повреждено 2, передано в инкубацию 6 → доступно 16; это условный пример. Купленные яйца не приписываются своим несушкам. Нельзя списать больше доступного. Продажа связывается с одной записью дохода.
5. **Корма:** покупка +20 кг за 800 ₽ создает приход на склад и 800 ₽ расход в финансах; кормление −2 кг не создает второй денежной траты.
6. **Напоминания:** «назначено», «сигнал отправлен», «выполнено», «пропущено», «перенесено» — разные статусы. Отправка сигнала не равна выполнению.
7. **Исправления:** связанные цифры пересчитываются вместе; сохраняются старые/новые значения, дата и причина. Обычное удаление не уничтожает историю; полное удаление данных — отдельная функция.
8. **Черновики:** поворот экрана, возврат из фона и обычное пересоздание интерфейса не теряют данные формы; черновик не проводит операцию до команды «Сохранить».
9. **Резервные копии:** отличать полную копию от CSV/PDF/Excel-отчёта; проверять файл перед восстановлением, не заменять данные без подтверждения и возможности безопасного восстановления.
10. **Источники:** профиль «Несушка» не означает, что любой инкубатор БИ-1/БИ-2 имеет все функции. Конфигурацию выбирают после модели. Функции и нормы только из применимых инструкций с указанием источника.

## 5. Рабочий протокол, предотвращающий повторения

**В начале каждого нового чата о «Наседке»:**
1. Прочитать `docs/PROJECT_STATUS.md` в GitHub (когда он туда будет добавлен), затем свежий `ROADMAP.md` и приложенные визуальные эталоны. При расхождении версий сначала указать расхождение, не выдавать старую информацию за актуальную.
2. Начать с раздела **«Точка продолжения»**. Не спрашивать заново об уже утверждённых решениях.
3. Выполнять **только текущую фазу**. Не переключаться автоматически на другой раздел и не создавать новый макет старого раздела.
4. После фактической работы менять `ПОСЛЕДНЕЕ СДЕЛАННОЕ`, `СЕЙЧАС`, `СЛЕДУЮЩЕЕ ДЕЙСТВИЕ`, статус задач и ссылки на результат. Подтверждать исполнение тестами/коммитом, а не изображением.
5. Для статусов пользоваться только: `УТВЕРЖДЕНО (UI)`, `ОПИСАНО В КОДЕ`, `ПРОВЕРЕНО`, `ЧАСТИЧНО`, `НЕ СДЕЛАНО`, `ЗАБЛОКИРОВАНО`. Никогда не смешивать UI-утверждение с реализацией.
6. GitHub считать эталоном **реального кода**, а утверждённые изображения — эталоном **дизайна**. Не заменять одно другим.
7. После записи в GitHub добавить явную ссылку на этот файл в `README.md` и убрать из устаревшего ROADMAP сведения, противоречащие актуальному состоянию, отдельной контролируемой правкой.
