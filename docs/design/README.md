## Замороженный дизайн

**ТРИ эталона уровня LOCKED:**
- `наседка_фермерский_ui_концепт.png` — **основной образец пяти экранов**.
- `Nasedka_Главная_утверждённый_шаблон.png` — **точный кадр Главной**.
- `Nasedka_Инкубация_эталон.png` — **точный кадр Инкубации**.

Эти изображения созданы раньше последующих отдельных макетов и определяют внешний вид. Нельзя заменять их иным UI без явно выраженного решения пользователя. Важны кремовая палитра, зелёные акценты, градиенты, карточки, иллюстрации птицы, компоновка, порядок кнопок и форма нижней навигации.

**Всегда четыре нижние кнопки:** `Главная`, `Новости`, `Журнал`, `Настройки`. Кнопки хозяйственных модулей — на Главной, напоминания — по колокольчику. Иконку приложения создаём последней.

Точное визуальное воспроизведение относится к композиции и стилю, но содержимое должно оставаться читаемым на других размерах дисплея; нельзя обрезать текст и создавать недоступные области ради механического соблюдения пикселей.

## Уровни утверждения

- `LOCKED`: точный неприкосновенный эталон.
- `APPROVED_CONCEPT`: направление и сценарий согласованы, детали графики и демонстрационные числа могут быть ошибочными.
- `PRESENTED`: показано, но конкретный макет не утверждён отдельно.
- `REFERENCE`: дополнительный или промежуточный рисунок.
- `SUPERSEDED`: заменён последующим решением; только история.

**Важно:** экран с заполненными значениями, галочками и датами — иллюстрация, не результат программной проверки. На ряде картинок неправильно активен `Журнал`, но это **не новое решение о навигации**.

## Что должно храниться для каждого экрана

- стабильный ID, название, модуль, краткий пользовательский сценарий;
- путь к **оригинальному** PNG, SHA-256 и статус утверждения;
- переходы/кнопки, обязательные и необязательные поля, пустые состояния, ошибки;
- источник данных (фактические записи пользователя, ручные измерения);
- связь с другими разделами и правила проверки;
- отметки «только концепция», «есть в коде», «проверено на устройстве» **отдельно**.

## Как избежать повторов

**До создания любого нового экрана** проверить [реестр](SCREEN_REGISTRY.md) и [решения](DECISIONS.md). Если он уже существует — продолжить детализацию или проверку, а не рисовать его заново. Если макет ошибочен — записать конкретную ошибку рядом с его ID; весь стиль не перерабатывать.

**После каждого этапа:** изменить `docs/PROJECT_STATUS.md` (сделано/теперь/дальше), реестр/журнал решений; добавить новую графику с хешем без удаления ранее утверждённого файла.
