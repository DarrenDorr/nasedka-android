## Реальное завершение процесса
RestoreProcessDeathTest находится исключительно в androidTest APK; нет нового экспортируемого компонента/производственного kill hook. Исключён из обычного connected suite посредством runner notClass. Скрипт tools/r1/process_death.py последовательно вызывает два am instrument для каждого из 6 случаев: prepared (NONE), first-db (PENDING), settings (PENDING), committed (COMMITTED, partial cleanup), rollback (PENDING), rolled-back-cleanup (ROLLED_BACK). Первое испытание записывает durable ready с PID и phase, вызывает Process.killProcess(myPid), не завершает JUnit успешно. Host требует ready, исчезновение PID (/proc), отсутствие OK; затем новая instrumentation с другим PID, проверка SQLite/managed prefs, phase, outcome, unrelated setting, успешный JUnit и durable verified. Артефакт JSON с PID и логами. Изолированные synthetic fixtures в files/r1-crash-fixtures, fresh emulator; не использовать на физическом телефоне. Actual process death не равен power cut или kill в середине отдельного syscall. Обычные Android tests 10+19, отдельные 6 сценариев не считать 12 обычными успешными тестами.

## Фактический ENOSPC
tools/r1/enospc.sh монтирует отдельный tmpfs 8 MiB на hosted Linux runner, с проверкой mountpoint; Java probe проверяет type/capacity (не более 16 MiB). Python создаёт реальные SQLite fixtures, Java production adapter выполняет prepare/PENDING и заполняет только ограниченный tmpfs до фактического kernel ENOSPC. Затем проверяет отказ реальной записи при apply, неизменность live hashes, PENDING и rollback files, освобождает filler и подтверждает recovery. SettingsPort in-memory, не Android SharedPreferences. Linux-only evidence, не доказательство ENOSPC на Android. sudo/mount может быть заблокирован инфраструктурой; не обходить gate и не заполнять общий диск. Android-specific ENOSPC остаётся OPEN. No power-loss claim.
