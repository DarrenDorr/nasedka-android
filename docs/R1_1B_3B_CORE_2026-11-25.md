## Реализация
Package-private Java DataAccessCoordinator; no Android/IO/callbacks under private metadata monitor. Immediate busy rejection rather than waiting for active operations (short monitor contention is possible; not lock-free). STARTING/RECOVERY_REQUIRED only allow RECOVERY reservation. READY permits SHORT or SNAPSHOT/RESTORE ticket. State RESTORE covers recovery as well as restore, Work distinguishes. Ticket is identity capability, exactly one claim/cancel wins; cancellation allowed only while pending, restores prior state; worker lease bound to claiming thread. SHORT nests LIFO same thread only, no upgrade, heavy lease cannot enter ordinary SHORT. Wrong thread/out-of-order release rejected, same-thread repeated close idempotent and cannot release different lease. All ordinary handles must close before lease. Root restore/recovery close without explicit finishVerified -> RECOVERY_REQUIRED, invalidates token; finishVerified(UUID) consumes lease after caller independently proves durable NONE and coherent persistent generation, NOT evidence by itself. No storage or callbacks inside coordinator. Snapshot/short close releases after resources closed by caller. In-memory UUID + identity epoch invalidate stale forms after verified restore or recovery even same UUID; check token atomically during admission; foreign coordinator/null token rejected. Persistent generation codec, notification identities, startup and real helper enforcement pending. No Activity reference; no cross-process protection; no claim of ANR prevention.
