# 🥚 Наседка — открытый помощник по птицеводческому хозяйству

**Версия исходников:** `0.5.0-dev` — проект в разработке. **APK в этом архиве нет.** Исходный код доступен по Apache 2.0; сборка на GitHub Actions ещё должна пройти проверку в реальном репозитории.

**Развитие продукта:** «Наседка» станет приложением для учёта птицы, выращивания молодняка, кормов, доходов и расходов, а в дальнейшем — домашнего хозяйства в целом. **Инкубация — отдельный модуль** с двумя сценариями: естественное насиживание птицей и инкубатор. [Новая концепция и этапы реализации](docs/PRODUCT_VISION.md).

**Первая версия главного экрана «Моё хозяйство» реализована в 0.3.0-dev.** Учёт поголовья, кормов и финансов пока не реализован; «Под наседкой» обозначен как будущий сценарий.

**Основной работающий модуль — инкубация в устройстве:** «Наседка» помогает вести закладки яиц, получать локальные напоминания, фиксировать температуру и влажность, изучать подсказки и сохранять историю. **Первый полноценный профиль: бытовые инкубаторы «Несушка» БИ-1/БИ-2** с таблицами воды по инструкции. Другие инкубаторы можно указать в ручном профиле без автоматического применения характеристик «Несушки». В будущих версиях добавим проверенные отдельные профили производителей.

**Это независимый проект**, неофициальное приложение производителя инкубаторов.

## Реализовано в исходниках

- Локальные закладки и напоминания, план по срокам, журнал и экспорт CSV — из версии 0.1.0.
- Два типа инкубаторов: профиль «Несушки» и универсальный ручной профиль. Неизвестным моделям **не назначаются** таблицы воды и заданная влажность «Несушки». Переход базы SQLite v1 → v2 без удаления записей.
- Раздел **«Новости»** с встроенной лентой и необязательной загрузкой публичного `content/news.json` из настроенного GitHub-репозитория. Если нет интернета, сохраняется последняя полученная лента.
- Проверка последнего **GitHub Release** по запуску/возвращению в приложение не чаще раза в 24 часа; есть ручная проверка. Источник выпусков зафиксирован в коде: `DarrenDorr/nasedka-android`.
- Три сборки: `github`, `play`, `rustore`. **Только GitHub-сборка** может скачать APK из GitHub Releases. Перед системной установкой сверяется SHA-256, указанный GitHub API, и требуется подтверждение пользователя и разрешение Android. Google Play и RuStore сборки сейчас направляют в магазин; интеграция их native update SDK предусмотрена позже.
- Подготовлена архитектура для будущей рекламы. **Рекламных SDK, рекламных объявлений и аналитического слежения сейчас нет.** Планы — в `docs/ADVERTISEMENTS.md`.
- Android 8.0+ (`minSdk 26`), компиляция/целевая версия API 36, Java 17, Gradle 8.11.1, Android Gradle Plugin 8.10.1.

## Как работают обновления

| Канал | Что уже сделано | Что осталось |
|---|---|---|
| **GitHub** | Проверка релизов, показ новой версии, загрузка APK, проверка SHA-256, запуск установщика Android | Публичный репозиторий, подписанные APK Releases, испытания на телефоне |
| **Google Play** | Отдельный flavor, переход в Google Play | Подключить Play Core In-App Updates, публикация и проверка |
| **RuStore** | Отдельный flavor, переход в RuStore | Подключить RuStore In-App Updates SDK после регистрации приложения |

**Важно:** Google Play запрещает самостоятельное обновление исполняемого кода через APK из других источников. Код, запрашивающий право устанавливать APK, присутствует только в `github` flavor. Установленный APK обновляется только при **совпадении идентификатора пакета и сертификата подписи** (или валидном механизме ротации), а также корректном номере версии. **Нельзя публиковать debug APK как релиз**: они имеют идентификатор `org.nasedka.app.debug` и тестовую подпись.

**Для Github release:** приложите **подписанный** `nasedka-github.apk` к релизу с тегом `v0.2.1` или выше. GitHub API должен сообщить его поле `digest: sha256:...`. Название файла обязательно. Новую версию следует собирать с более высоким `versionCode` и тем же постоянным сертификатом подписи, что предыдущая. Без проверяемого SHA-256 приложение не предложит установку.

Код GitHub-обновления пока не проверен на реальном устройстве. Сторонний пользователь не должен использовать этот архив как готовый релиз.

## Новости

Базовые новости лежат в `app/src/main/assets/news.json`; редактируемый публичный источник — `content/news.json`:

```json
{
  "items": [
    {"date":"2026-11-17", "title":"Название новости", "text":"Описание новости"}
  ]
}
```

Исходный адрес новостей закреплён в коде: `DarrenDorr/nasedka-android`. Лента берётся с `https://raw.githubusercontent.com/DarrenDorr/nasedka-android/main/content/news.json`, без API-токенов и учётных записей.

Доступ к GitHub является необязательным: инкубационный календарь, все напоминания, журнал и инструкции продолжают работать офлайн.

## Сборка через GitHub Actions

1. Создайте публичный репозиторий `nasedka-android`. Загрузите **содержимое папки** проекта в корень, а не сам ZIP.
2. Перейдите в **Actions → Android build and tests → Run workflow** или сделайте push в `main`.
3. Workflow должен запустить `testGithubDebugUnitTest`, собрать `assembleGithubDebug`, `assemblePlayDebug`, `assembleRustoreDebug` и дать тестовые APK в артефактах.
4. Установите **только GitHub debug APK** для тестирования. Разрешите уведомления и при необходимости точные напоминания. Проверьте события и доставку уведомлений на нескольких Android-версиях.

**Локальная сборка:** JDK 17, Android SDK 36, Gradle 8.11.1 (или создайте wrapper `gradle wrapper --gradle-version 8.11.1`). Затем:

```sh
gradle testGithubDebugUnitTest assembleGithubDebug
```

Готовый тестовый APK ожидается в `app/build/outputs/apk/github/debug/`. Ключи подписи и токены **не добавляйте в GitHub**. Порядок публикации и требования магазинов — `docs/DISTRIBUTION.md`.

Руководство содержит разные интервалы автоматического переворота (1 и 4 часа); настраивайте параметры своего устройства.

## Звук уведомлений и экран блокировки (0.2.3-dev)

Новые каналы `Проверки и уход — со звуком` (обычный уровень) и `Важные этапы и тест — со звуком` (высокий уровень) создаются с системным звуком уведомления и вибрацией. Каналы предыдущих версий нельзя перенастроить программно после их создания. Управление звуком и видимостью остаётся за пользователем через системные настройки; «Не беспокоить» и тихий режим имеют приоритет.

В приложении: **Настройки → Звук и экран уведомлений** — диагностика каналов и ссылки на настройки каждого канала. На HONOR: **Настройки → Уведомления → Другие настройки уведомлений → Включение экрана** для попытки пробуждения экрана. Приложение **не запрашивает** `USE_FULL_SCREEN_INTENT`, не обходит блокировку и не гарантирует пробуждения экрана при любых ограничениях MagicOS.

Проверяйте два сценария: тест «Показать сейчас» (звук/вибрация) и тест «Через 2 минуты» при заблокированном экране (время и звук). Это тестовые, а не подписанные магазинные APK. Установка нового debug APK поверх старого может не пройти, если их подписи различаются; не удаляйте приложение с важными данными без резервной копии.

## HONOR X7b: улучшения интерфейса 0.3.1-dev

После первого физического тестирования нового экрана «Моё хозяйство» сокращено дублирование переходов к инкубации, карточки будущих модулей собраны в один компактный блок, а пустой журнал предлагает переход к реальной закладке. Запрет уведомлений для всего приложения теперь отделён от отключения конкретного канала. Добавлен прямой переход в системные разрешения Android. Кнопка продолжения установки APK появляется только при существующей загрузке в Android DownloadManager.

В скриншотах физического теста **системные уведомления запрещены**, хотя точные будильники доступны. Перед тестами напоминаний включите в настройках Android уведомления приложения и необходимые каналы. Успех фоновой доставки предыдущей сборки не доказывает, что в новой установке разрешения предоставлены. Безопасное обновление debug APK с сохранением SQLite ещё не подтверждено на физическом устройстве.

## HONOR X7b: проверка бесшумных уведомлений (0.3.2-dev)

В физическом тесте сигнал фонового AlarmManager пришёл с задержкой 1 секунда; уведомления разрешены, точные будильники доступны, но звук не слышен и заблокированный экран не загорается. В приложении «звук настроен» означает только ненулевой URI канала, а не фактически воспроизведённое аудио.

В **Настройки → Звук и экран уведомлений** добавлена диагностика: режим звонка (обычный/вибрация/без звука), текущая громкость потока уведомлений, режим «Не беспокоить», выбран ли системный звуковой сигнал. Кнопка «Прослушать системный сигнал» запускает звук *только по явному действию пользователя* через системную службу Android, без обхода беззвучного режима и DND. Кнопка «Открыть громкость и звуки Android» ведёт в системные настройки.

**Важно:** фоновые оповещения не запускают собственное воспроизведение звука, так как в Android звук и вибрация контролируются каналом уведомлений и системными настройками. Включение экрана — настройка HONOR «Wake screen» в параметрах уведомлений, приложение не может её гарантировать. Полноэкранные системные разрешения не запрашиваются, `USE_FULL_SCREEN_INTENT` не добавлен.

Для ретеста на HONOR X7b сравните два сценария: звук кнопки предпрослушивания и звук уведомления через две минуты при заблокированном экране. Измерение задержки не равно проверке звука.

## Подготовка к инкубации — первый мастер (v0.4.0-dev)

**Путь:** «Инкубация» → «В инкубаторе · подготовка и закладка» → (1) выбор «Несушка» и вместимости 36/63/77/104 яиц или другой модели с ручным профилем → (2) проверочный список → (3) параметры закладки и создание.

Для «Несушки» пункты подготовки сверены с исходным руководством `incubat_2021.pdf` (2021), разделы 1, 4, 6, 7. Приложение показывает ссылки на пункты и страницы. Для сторонних инкубаторов только универсальный проверочный список **без** заводских норм «Несушки»; у пользователя должна быть собственная инструкция. Приложение не может подтвердить выполнение пунктов физически.

**Температура больше не предзаполнена значением 38,0 °C** при создании партии: это заводская настройка из руководства, не единый режим для всех птиц. Пользователь обязан указать своё значение, как и срок. Выбранная на шаге 1 модель закреплена на шаге 3: для изменения требуется заново пройти подготовку.

После подтверждения все отметки этапа подготовки кратко фиксируются в **журнале той же закладки**. Сохранение партии и записи выполняется в одной SQLite-транзакции, без миграции схемы и без изменения активных партий. Сами измерения остаются только ручными. Инкубация под птицей-наседкой, полноценная посуточная таблица и отдельные профили других производителей — следующие этапы.

## Исправление случайного поворота телефона (v0.4.1-dev)

**Замечание физического теста HONOR X7b:** при случайной смене портретной и альбомной ориентации Android пересоздавал главную Activity и закрывал незавершённые диалоги — в том числе выбор модели инкубатора, чеклист подготовки и ввод закладки.

**Исправлено:** MainActivity обрабатывает изменения `orientation|screenSize|smallestScreenSize|screenLayout|keyboardHidden` самостоятельно, сохраняя уже открытый Android-диалог и его поля при повороте. Ориентация экрана **не блокируется** — горизонтальное использование поддерживается. При прочих пересозданиях Activity сохраняются выбранная вкладка, текущая закладка и ID экспорта.

**Ограничение:** незавершённые поля диалога пока не записываются в постоянный черновик, поэтому после принудительного закрытия приложения, смены языка, уничтожения процесса системой или иных пересозданий диалог может быть утрачен. Это отдельная будущая задача — полноценное восстановление черновиков мастера, с проверкой сохранности данных.

**Ретест:** шаги 1/2/3 мастера повернуть 2–3 раза между вертикальной и горизонтальной ориентацией; проверить выбранную модель, уже отмеченные пункты, текст/числа и выбранное время, затем сохранить тестовую закладку и проверить журнал. Также проверить окна «Записать наблюдение», «Завершить инкубацию» и настройки расписания. В коде нет принудительной блокировки ориентации.

## Дневник «День за днём» — 0.5.0-dev

В деталях каждой инкубации появляется кнопка «Таблица инкубации · день за днём». В таблице локальные даты от первого дня до **отдельного ожидаемого дня вывода**. Каждый день можно раскрыть: плановые события из существующего календаря, отметки выполнения, ручные измерения температуры/влажности и пользовательские записи. Отсутствующий факт не выдается за 0.

Для наступивших, но не отмеченных событий активной партии можно поставить отметку, не закрывая таблицу. Новые данные не генерируются: читаются существующие SQLite v2 `entries`/`done`, календарь `Plan`. Длительный перечень «Ближайших действий» сокращён до трёх карточек. Исправлены «1 яиц» и подписи скрытых полей другого инкубатора. Исторический план после завершения инкубации не реконструируется — остаются сохранённые записи и отметки.

Новая таблица требует физического ретеста HONOR X7b. Звук и Android-уведомления специально не менялись; подсветка экрана остаётся неподтверждённой возможностью.
